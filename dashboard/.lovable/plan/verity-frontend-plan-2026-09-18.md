# Verity frontend plan

## Goal
Build a complete, responsive financial-crime analyst workspace at `/`, using the selected **Clay forensic relief** direction and the repository’s real product language, contracts, and mock cases.

## Experience
- Create a sticky Verity masthead with queue health, sync state, and analyst identity.
- Build a filterable case rail for card fraud, real-ledger anomalies, and synthetic-network cases.
- Make case selection update the investigation title, risk score, evidence, factors, trace, and query suggestions.
- Preserve the selected asymmetric desktop composition while stacking the workflow clearly on phones and tablets.
- Use warm paper, ink, signal red, amber, and teal tokens with Bricolage Grotesque, IBM Plex Sans, and IBM Plex Mono.

## Investigation workspace
- Render the three repository cases with their actual IDs, amounts, scores, statuses, narratives, and trace events.
- Add working tabs for a real-ledger timeline and a custom transaction-network view, clearly labeling synthetic evidence.
- Show case-specific risk factors and honest boundaries between interpretable signals and anonymized model dimensions.
- Build a citation-linked reasoning trace using actual `AgentTraceEvent` IDs.
- Add an interactive counterfactual panel with prepared, transparent frontend responses and visible processing states.
- Include analyst actions with clear local UI feedback, without pretending they write to a production system.

## Structure and quality
- Create small reusable frontend pieces for the masthead, filters, case items, risk summary, evidence views, reasoning trace, and query panel.
- Define the chosen visual system as semantic tokens in the global stylesheet; avoid generic dashboard defaults and decorative AI effects.
- Add restrained entry, evidence-drawing, tab, and status motion with reduced-motion support.
- Add unique Verity metadata for the home route and replace all placeholder metadata.
- Verify the live page at desktop and mobile widths, checking interactions, overflow, console errors, and the latest preview build signal.

## Scope boundary
This phase builds the polished frontend against the repository’s supplied mock data. It will not migrate or host the Python detection APIs, train models, add authentication, or persist analyst decisions.
